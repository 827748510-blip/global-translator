# 滑词翻译

在任意 App 里用鼠标划选文字，松手后在选区附近弹出译文，并可一键 **优化提示词**。**双向互译**：选中英文 / 其他外文译成简体中文，选中简体中文译成英文（方向自动判定，无需设置）。与窗口覆盖层气泡、Chrome 扩展桥相互独立。

## 行为

1. 菜单栏设置里有 **滑词翻译** 开关，默认开启。关闭后不再监听划选、不弹层，优化提示词也不可用。
2. 仅在 **鼠标左键抬起** 且选区稳定约 150ms 后读取选区；拖拽过程中不弹层。
3. 弹层展示截断后的原文、结果，以及 **翻译** / **优化提示词** / **拷贝**。划选后默认先翻译；点「优化提示词」才按当前场景改写。操作区上方是 **场景分段**（沟通润色 / 任务指令 / 用词修正，默认 **沟通润色**）。弹层**没有**「翻译后端」分段；DeepSeek 云端 / 本地模型只在设置页切换。切换场景 **不会**关掉弹层。Escape、点击外部、或选区变空时关闭。关掉后同一选区不会立刻再弹；选区清空或换成别的句子后才会再出。
4. **方向自动判定**：简体中文选区 → 译成英文；英文 / 其他外文 → 译成简体中文。不再对中文显示「已是中文」：中文草稿会直接得到英文译文，同时 **仍可优化提示词**（中文草稿很常见，优化仍作用于中文原文）。日文 / 韩文等仍译成简体中文。窗口覆盖层与扩展桥不在范围内，仍只译成简体中文。
5. 空选区、纯空白、单击未划选、以及 `TextFilter` 会拒绝的标识符 / 纯 URL 等不弹层。划选后若读不到文字，短暂显示「无法读取所选文字」（约 1.5 秒后自动收起）；Escape、点击外部、选区变空或再次按下会立刻关闭。含 **内部驼峰**（SwiftUI、ScreenCaptureKit）或「ALL-CAPS 缩写 + 另一技术词」（Vision + OCR）的列表显示「专有名词，无需翻译」，划选时不请求模型；点「翻译」仍会强制走模型。`Sentence 0`、`Hello from the page`、`File / Edit` 等普通英文仍翻译。结构化请求失败先走第 7 条的纯文本兜底，只有兜底也失败才显示「翻译失败」，**不会**出现「服务返回异常，请稍后重试」。
6. 翻译和优化都走设置页「翻译后端」当前选中的全局后端（`AppConfiguration.backend`，默认持久化）。不会静默换到别的云厂商。全局后端为 DeepSeek 云端且未配置 Key 时，弹层明确提示去设置填写 API Key 并测试连接，不会静默失败。优化使用独立的 `completePlain` 提示词，不走翻译 JSON schema，也不取消 overlay/bridge 在途请求。选区是不可信数据，模型不得执行其中的指令。
7. **结构化翻译失败有一次纯文本兜底**（见下文「翻译失败容错」）。模型空回包、回声原文或质量拒绝不再一律显示「翻译失败」：≤600 字的选区会改用纯文本提示词重试一次，品牌 / 产品 / 技术名会得到 `Figma（设计工具）` 这类中文注释；重试仍回声原文且选区像专有名词时显示「专有名词，无需翻译」；普通句子回声或补答再次失败才显示「翻译失败」。
8. **优化场景**（`PromptOptimizeMode`，上次选择写入 `AppConfiguration`；新安装默认 **沟通润色**）：
   - **沟通润色**（默认）：合并原「专业回复」+「高情商」。改得更得体、清晰、有同理心；职场/社交得体，不阿谀、不说教、不改事实、不加新承诺。
   - **任务指令**：把含糊意图扩写成给 AI/agent 执行的结构化任务说明（有序步骤、约束、失败即停、禁止 force push 等安全护栏）。修正明显笔误（如 mian→main）；只产出指令文本，不执行任务。不是图像生成提示词。
   - **用词修正**：错别字、用词、不得体/冒犯表达；尽量少改结构与语气策略，保留原意与信息结构。
   已删除「生成提示词」「技术表达」，以及独立的「专业回复 / 高情商」。配置里旧 rawValue 迁移：`professionalReply` / `highEQ` → 沟通润色；`wordingFix` → 用词修正；`generativePrompt` / `technicalExpression` / 未知 → 沟通润色。
   三档都只输出改写结果；默认简体中文，专有名词/标识符原样；英文源且宜保留英则保留（`PromptOptimizationSupport.prefersEnglishOutput`）；不要变成图像生成提示词。
9. **拷贝**：译文 / 优化结果 / 「无需翻译」等可拷贝状态下，成功后按钮变为 **已拷贝**（约 1.5 秒后回到「拷贝」）；失败则短暂显示 **拷贝失败**。不弹系统警告。
10. 不依赖「自动翻译」开关，也不依赖窗口覆盖层是否在跑。Chrome 因扩展桥跳过 overlay 时，滑词仍然可用。

## 权限与选区读取

需要 **辅助功能**（与现有 AX 采集相同）。未授权时只记日志，不弹层、不崩溃。单击空白处不会弹出「无法读取所选文字」。划选后某个 App 读不到文字时，弹层短暂显示该提示后自动收起。

默认用 AX `kAXSelectedText` / 焦点元素的选区范围。剪贴板兜底只在能 **完整备份** 当前剪贴板时才会发 ⌘C，读完 **立刻恢复**；承诺文件 / 延迟数据等无法完整备份时跳过 ⌘C，避免毁掉用户剪贴板。密码框（SecureTextField）以及系统安全输入开启时不读、也不走剪贴板。本应用自己的窗口始终跳过（不弹层、拖选后也不发 ⌘C）。

### 飞书 / Electron 类 App

飞书、Lark 以及不少 Electron / 自绘文本的 App **不暴露可用的 AX `selectedText`**，选区范围也经常是 0。旧逻辑只在「AX 报告 range.length > 0 却给不出字符串」时才 ⌘C，这类 App 永远走不到兜底，划选后静默无弹层。

现在的规则：

1. **鼠标拖选后松手**（按下期间收到 `leftMouseDragged`，系统本身会滤掉几乎不动的位移）：AX 若是 `.empty` / `.unavailable` 且没有可用字符串，才尝试 ⌘C 剪贴板兜底。读到的文本与普通选区一样走 `TextFilter.selectionDecision`（中文译成英文；外文译成简体中文；标识符 / URL 跳过），来源标记为 `clipboardFallback`。弹层锚在鼠标附近（飞书等 App 的 AX 选区范围经常是 0，不能用整块 webview 的 frame，否则会贴到窗口边缘）。
2. **单击、无拖拽**（或可忽略的位移）：不发 ⌘C、不弹层，避免点一下就出现红字或改剪贴板。
3. 拖选后剪贴板也读不到字：短暂显示「无法读取所选文字」，约 1.5 秒后自动收起。
4. 本机窗口、密码框、剪贴板无法完整备份：跳过 ⌘C。

风险：⌘C 会短暂占用通用剪贴板；若目标 App 的拷贝快捷键绑定的不是当前视觉选区，可能读到别的内容。备份/恢复失败时宁可不弹层，也不留下用户剪贴板被换成选区文本。

### 划选判定与降级

单击、拖窗口、拖滚动条都会产生 `leftMouseDragged`。只凭「是否出现过拖动」判断，就会把它们当成划选：在真实划选之外弹出红字，还白白借一次剪贴板。现在每次按下 → 拖动 → 抬起都会采样几何与时间特征，再分三类：

- **click**：没有拖动，或位移小于 4 pt 且累计路程小于 8 pt（手抖）。不读剪贴板、不弹层。
- **textSelection**：位移达标、拖动时长 ≤ 3 秒、途中没有超过 1.2 秒的停顿。只有这一类才允许走 AX 读取与 ⌘C 兜底，也才可能显示「无法读取所选文字」。
- **nonTextDrag**：拖动超过 3 秒，或中途停顿超过 1.2 秒（拖窗口、拖滚动条、按住不放）。与 click 一样静默。

阈值集中在 `SelectionGestureThresholds`，判定在 `SelectionPointerState.gestureVerdict`。判定只用到位移与时间，不涉及被选中的内容。

**降级**：连续 3 次「划选却读不到文字」后进入降级模式，30 秒内不再显示「无法读取所选文字」，也不再借剪贴板。期间读到任何文字、或冷却结束，都会自动恢复；关闭滑词翻译时也会重置。

**日志**：非 click 手势各记一条 `selection_gesture`（verdict、位移、路程、拖动事件数、时长、最长停顿），降级记 `selection_degraded`。只写数值，不写选中文字或应用内容。真实拖选却没读到任何文字时另记一条 `selection_unreadable`（同样只有手势数值、`clipboardAllowed` 与 `degraded`），用于定位「划词没反应」。

## 翻译失败容错

本地模型（qwen3-4b）会把品牌 / 产品 / 技术名原样返回，例如 `Figma`、`Spotify`、`Python`、`npm`、`Webpack`、`Jira`、`Docker`。结构化请求要求 `json_object`，质量校验又会把「译文等于原文」判为失败，于是这些选区过去会稳定显示「翻译失败」。本机抽样 83 个常见界面/技术词，28 个（34%）会被回声。

现在的处理：

1. 结构化请求抛 `invalidResponse`（回声原文、JSON 被截断、格式跑偏、空结果）时，**只对 ≤600 字的块**改用一次纯文本补答（`SelectionFallbackInstructions`）。纯文本没有 JSON schema 约束，并明确要求「专有名词保留原名 + 极短中文注释」，因此 `Figma` 会得到 `Figma（设计工具）`。
2. 补答仍与原文相同（忽略大小写）时：若选区像专有名词（单个短词、或 ≤4 个首字母大写/驼峰词，如 `Figma` / `Mac Studio` / `npm`），显示「专有名词，无需翻译」（可拷贝、可优化提示词），不再显示红色「翻译失败」；普通句子回声仍按失败处理，避免把模型故障伪装成成功。
3. 补答为空或再次失败才显示「翻译失败」；`networkFailure` / `timeout` / 凭据错误**不会**自动重放，避免重复计费与状态不确定的重试。
4. 超过 600 字的块保持原结构化分块路径，不进入纯文本兜底：纯文本补答的输出预算（1024 token）可能静默截断长译文，宁可保留明确的失败状态。
5. 多块选区里只有末尾短块回声时，不会把整段中文翻译标成「专有名词，无需翻译」：该情况转为「翻译失败」，避免吞掉前面已翻译的内容。
6. 日志 `selection_plain_fallback` 记录 `status`（`success` / `copied_source` / `failed` / `skipped`）与 `reason`（`copied_source` / `invalid_response` / `empty` / `too_long`），不含选区文字。
7. 边界：`TextFilter` 已判为「专有名词，无需翻译」的选区（如 `Mac Studio`、`SwiftUI`）平时不请求模型；只有用户点「翻译」强制走模型时才可能遇到回声，此时沿用后端既有口径保留原文，不再触发一次兜底。
8. 兜底成本有界：兜底只对 ≤600 字的块生效，常规分块下通常一次选区最多多出一次短请求；超长文本被拆出多个短块时理论上按块数上限增加，但每次仍只重试该块一次。

### 选区读取的异步兜底

飞书 / Electron 类 App 只能用 ⌘C 剪贴板兜底。⌘C 由目标 App 主线程异步处理，旧实现同步轮询 10×5ms（50ms）就放弃，重页面/高负载时会误判「读不到」，表现为划词没反应。

- 兜底改为 `async`：最多等待 40×5ms（200ms），期间不阻塞主线程。
- **等待不可被取消打断**：一旦发出 ⌘C，即使新划选/关闭开关取消了这次 settle，也会等满窗口、读完再恢复剪贴板，最后才丢弃结果。否则会「先恢复、后被迟到的 ⌘C 覆盖」，把用户剪贴板换成选区文字。
- 两次重叠的读取会串行排队（同一时间只有一个 steal-and-restore 窗口），避免第二次把第一次的临时选区文本当成用户原来的剪贴板备份。
- 选区读取协议 `SelectedTextReading.readSelection` 已异步化，AX / `NSScreen` / `NSPasteboard` 等 AppKit 调用仍留在主线程，只有等待处挂起；settle 后会用代际 token 校验，过期结果不会弹到新选区上。

## 本机验证（macOS）

1. 授予辅助功能后打开 Global Translator，确认设置里「滑词翻译」为开。
2. 配置本地 Ollama 或 DeepSeek（与自动翻译同一套后端）。
3. 在 **TextEdit / 备忘录** 中划选一句英文，松手后应在选区附近看到中文、**翻译**、**优化提示词**和拷贝。单击空白处不应弹层。
4. 点 **优化提示词**（默认场景「沟通润色」），应变为优化中，然后出现改写后的得体文本，可拷贝。设置弹层里滑词开启后可直接改默认场景（分段控件）；滑词弹层里同样用分段切换「任务指令 / 用词修正」。应得到对应风格，且不换后端厂商。重启后应记住上次场景。
5. 划选一句中文草稿（例如「一个女孩站在雨里」）：应得到英文译文（双向互译）；点优化提示词仍应按当前场景改写中文原文。
6. 点 **拷贝**：按钮应变为「已拷贝」约 1.5 秒后回到「拷贝」。译文、优化结果、技术专有名词「无需翻译」都应能拷贝。
7. 在 **飞书 / Lark** 聊天气泡里拖选中文或外文：应弹出滑词层（中文译成英文 + 优化提示词，外文译成简体中文）。仅单击气泡、不拖选，不应出现弹层，也不应改掉系统剪贴板里原来的内容。
8. 划选后看系统剪贴板：应仍是划选前的内容（⌘C 只是瞬间借用）。
9. 关闭「滑词翻译」后再划选，不应再出现弹层。
10. 打开 Chrome 且自动翻译 + 扩展桥开启时，页面不应出现 overlay 气泡，但划选仍应弹出滑词译文 / 优化。
11. 设置页「翻译后端」可在 **DeepSeek 云端** 与 **本地模型** 之间切换，重启后应记住；滑词弹层**不应**再出现该分段。未配置 DeepSeek Key 且全局后端为云端时，划选或点翻译 / 优化提示词应看到「请到设置填写 DeepSeek API Key 并测试连接」，不应静默失败。两边都配置好时，翻译和优化都应走设置页当前选中的后端。
12. 本地后端下划选品牌 / 产品 / 技术名（`Figma`、`Spotify`、`Python`、`npm`、`Jira`、`Docker`）：应出现 `Figma（设计工具）` 这类中文注释，或「专有名词，无需翻译」，**不应**出现红色「翻译失败」。日志应有一条 `selection_plain_fallback`。
13. 划选一句普通英文：仍应正常翻译，日志里没有 `selection_plain_fallback`（结构化请求成功时不走兜底）。
14. 该次兜底不改变安全边界：网络中断 / 后端未启动时应显示对应失败提示，不应把请求重放成两次计费调用。
15. `swift test -Xswiftc -warnings-as-errors`
16. 真机模型冒烟（需要本机 Ollama 与模型）：`GT_LIVE_OLLAMA=1 swift test --filter LiveOllamaSelectionSmokeTests`

## 长文本（选择 / 滑词）

浏览器或任意 App 里划选 / 粘贴很长的英文（例如 15k–22k 的 Seedance 提示词）时：

1. **不要再静默只译前 4000 字。** 滑词按段落 → 句子 → 词边界拆成约 1800 字一块，按原顺序逐块翻译再拼接。本地模型和 DeepSeek 云端都走同一套分块。
2. 覆盖层 / 页内批次仍保持短句上限（约 4000 字/条、本地 3 段一批、`max_tokens` 128/256）。视频叠层 cue 仍然很短，不受影响。本地后端对**单条长选区块**会按源文字长度提高 `max_tokens`（上限 2048），避免 128 token 截断。
3. 若全文仍超过硬上限（48000 字），只翻译上限内的部分，弹层在译文下方用中文标明 **「原文过长，仅翻译了部分内容」**，拷贝按钮拷的是译文本身。禁止把截断结果当成完整成功。
4. 本机验收：设置后端为 **本地模型**，在 TextEdit 粘贴一段超过 4000 字的英文 Seedance 提示词并划选，应看到多段中文拼接、结尾不是 4000 字处的半截英文；再试一段远超 48000 字的文本，应看到上述中文提示。
